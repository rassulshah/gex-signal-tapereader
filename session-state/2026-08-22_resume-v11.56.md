### ⛔ THE TAPEREADER'S `ifFetch` MUST STAY OFF — I RECOMMENDED FLIPPING IT ON AND I WAS WRONG
A cross-origin fetch needs `@grant GM_xmlhttpRequest`. The tapereader runs **`@grant none`, and that is
LOAD-BEARING**: it keeps the script in PAGE context so its `window.fetch` / `XMLHttpRequest` hooks capture
Skylit's `gex/levels` feed. Any `@grant` moves it into Tampermonkey's sandbox where `window` is a wrapper
and the hooks patch the wrapper — **the tape goes dark.** This is stated in the source at the `IF_LS`
declaration and it is why `IF_CFG` defaults `{on:false}`. The tapereader's `ifFetch`/`ifParse`/`ifLevels`
are DEAD CODE kept for reference. **The companion holds the grant; anything cross-origin belongs there.**

**Five failures were ONE bug in the shared `ex()` harness, repeated five times.** `ex()` extracts a single
function BODY and `eval`s it, so any name that body closes over throws `ReferenceError` inside the eval
and the file scores zero — indistinguishable from a real failure. If a test in this suite ever goes red
with a `ReferenceError` for a name that clearly EXISTS in source, this is why: add the callee to the eval
list, and pull module-level constants FROM SOURCE with a regex rather than hardcoding them.

⚠ **`eval()` inside a `forEach` callback declares into the CALLBACK's scope.** Join and eval once. Already
in the notes, and it cost time again during this very fix.

- **SCALES:** `em` is SPX → chart via `dispScale`; candles are UNDERLYING → chart via `rr`. Both land on
  chart scale before anything is compared or drawn, and only then is `dispNum()` safe.
- **`emPos()` CLAMPS.** A mark outside the band pins to the rail; the percentage says how far past.
- The percentage is **displacement from the open ÷ EM** — user's choice over range-travelled, so the dot
