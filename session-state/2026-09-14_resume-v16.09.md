## ⚠⚠ THE DAY MODEL — MEMORISE THIS, DO NOT RE-DISCOVER IT

The operator lost time because a context did not know the day model. It has **two evidence bases that are
never fused**, and **two rendered pieces**:

**The geometry / candle model — the EXPECTED candle.** Fed by `hodlodBaseFor(weekday)` →
**`BASERATES.json` / `HODLOD_BASE`** — **297 ES sessions** (2025-06-02 → 2026-09-10), per weekday, trimmed
mean (Tukey 1.5×IQR excluded), pt_usd 50, RTH 08:30–15:00 CT, tool grid (3-min bars stamped by END, open =
the 08:30 RTH open). Per weekday it carries: `firstClock`/`secondClock` (sec-of-day), `tookMin`/`gapMin`,
`rngPts`/`rngUsd` (+ `rngP25`/`rngP75` IQR band), `lodFirstPct` (which extreme prints first), and the
**wick family** `{ wick, bop, mud, wickPct }` (durations in minutes; wickPct a price ratio). Anchored on
TODAY's actual RTH open; range split symmetrically (v1 — "blended with the IF EM"; a directional-close model
is a later refinement). **These are the model's real per-weekday numbers, not one-day samples.**

**The READ / classifier — SEPARATE, never in the candle.** `tools/model-lodhod.py` (HLTAB, **AUC 0.879**,
grouped CV, calibration, ablation) is a two-axis lookup table (`posr` × minutes-since-open) that answers
"has the HOD/LOD already printed?" (`LOD IN — 84%`). It is the READ box + the elapsed-time ladder (Block 2/3
of the §10.2 spec). **It is NOT the candle geometry and is NOT written to the CSV.** Adding a third axis made
it worse (0.8729). Two axes. See `mockups/hodlod-v2-SPEC.md` and FINDINGS F-4.

> If a future context is unsure which model the candle uses: it is **BASERATES.json via `hodlodBaseFor(dow)`**.
> If it is unsure what AUC 0.879 refers to: the **classifier/READ**, a different layer. Do not merge them.

**The two rendered pieces:** (1) the **candle** = `lsDayModel.dll` (BUILT, v0.7). (2) the **stats strip** =
`lsDayStats.dll` (source READY this session, v0.1, not yet compiled/tested) — §10.2 Block 1, two rows A/E.

## THE GammaProfile.csv SCHEMA (the ONE contract between the panel and all RTX plugins)

Written by `gammaProfileBuild()` → `gammaProfileExportNow()` into
`%USERPROFILE%\InvestorRT\rtx\lsFlexLevels\GammaProfile.csv` (same folder as FlexLevelsExport.csv, untouched),
on the 180s IRT tick + the ⇩ now button + grant paths, behind `CFG.irt.profileOn` (default on). Everything in
the **current futures symbol's price space** (front-month auto-roll, v16.01). Each plugin ignores rows it
doesn't own.

```
STRIKE,<esPrice>,<%King>,<rank>,<kingFlag 0|1>   gamma node  (lsGammaProfile)   from tapeMapLive('SPXW')
KING,<esPrice>                                   the King node price
SPOT,<esPrice>                                   latest close (ES-native)
BOOK,ES                                          which chart family the file is in
WEEKDAY,<Mon..Fri>,<date e.g. "11 Sep">          day-of-week + date header
--- day candle (lsDayModel) ---
DAYACT,<o>,<h>,<l>,<c>                            actual developing candle       hodLod + sessionBody
DAYHOD,<value>,<clock>,<duration>                actual HOD tip (clock string, "Xh Ym")
DAYLOD,<value>,<clock>,<duration>                actual LOD tip
DAYMUD,<±pts>,<duration>,<dollar>                MUD box inside the body
SWEPT,<PDH|PDL|ONH|ONL|PWH|PWL|PFH|PFL>,<esPrice>,<clock>,<R|B|T>   swept high/low
DAYEXP,<o>,<h>,<l>,<c>                            expected candle  hodlodBaseFor(dow), anchored on today's open
DAYEHOD,<value>,<clock>,<duration>               expected HOD tip
DAYELOD,<value>,<clock>,<duration>               expected LOD tip
DAYEMUD,<+pts>,<duration>,<dollar>               expected MUD
--- stats strip (lsDayStats) — v16.09, 17 fields, raw units (plugin formats) ---
DAYSA,first,firstPx,firstClkSo,tookMin,bopMin,wickMin,wendSo,wickPct,mudMin,second,secondPx,secondClkSo,gapMin,rngPts,rngUsd,,        (actual; rngP25/P75 empty)
DAYSE,first,firstPx,firstClkSo,tookMin,bopMin,wickMin,wendSo,wickPct,mudMin,second,secondPx,secondClkSo,gapMin,rngPts,rngUsd,rngP25,rngP75   (expected)
   clocks = raw sec-of-day (int); durations = raw minutes; prices = 2dp; empty = unknown.
   strip columns: 1ST·[1st]·Took·BOP·Wick·W.End·Wick%·MUD·MUDt(=HL Gap−BOP)·2ND·[2nd]·HL Gap·HL Rng
--- king tracker (lsKingTracker) — v16.09 ---

```

**Data functions the build uses (so they're not rediscovered):**
- `hodLod(sym)` — day measurement: `ok, hod, lod, hodT, lodT, first/second (+T), took, gap, rngPts, rngUsd,
  wickPct, wend, bop, wick, mud, reclaimed, open, scale, ...`. `sym = activeSym()`.
- `sessionBody(sym)` — `{open, close, hi, lo}`.
- `hodlodBaseFor(dow)` — the expected model (normalised: `tookMin, gapMin, rngPts, rngUsd, rngP25, rngP75,
  firstClock, secondClock, lodFirstPct, wick{wick,bop,mud,wickPct}, basis{n,pooled}`).
- `sweepEventsShown(sym)` — swept levels (`level, px, at [clock STRING], status`).
- `esOfSpx(spxPx)` — SPX→ES via `skylitFutPx('ES1','SPXW',k).px` (ratio ~1.0003), persisted `GP_SPXWR_KEY`.
  **NOT `R.r`** (the ~10× SPY ratio).
- `futDerBookKing(futSym, sources)` — a book's King in the FUTURES price space, straight off the derived
  payload: `.k` (futures price), `.strike`, `.pct` (signed ±100), `.src`, `.why`. Sources per book:
  ES1 → SPX `['SPXW','SPX']`, SPY `['SPY']`; NQ1 → QQQ `['QQQ']`, NDX `['NDXP','NDX']`. Both ES1 and NQ1
  derived payloads are self-fetched every 60s while the export is on (`selfFetchFut`), so all four populate
  regardless of which chart is active.
- Debug: `window.__gptsDebug.gp()` (preview rows) · `.gpExport()` (force write) · `.futDer()` (derived books).

## ⚠ THE ONE THING TO VERIFY LIVE TOMORROW (calibration, not a code bug)

The King tracker maps a roll's **CT clock** (CSV) to a chart bar via the machine's local time. If IRT's chart
timezone ≠ CT, the steps land at the wrong X. There is a **"Clock offset (min)"** setting on lsKingTracker for
exactly this — tune it once against the live chart (compare a known roll time to where the step lands). Same
idea if `RTARRAYI(barDateTime)` needs different handling on his platform — the fallback scan covers a
non-populated search, but confirm the steps sit at the right times before trusting them.

Also confirm on the ES chart: the `KINGNOW` SPX level should sit on the gamma-profile **magenta King** at the
open (the FlexLevels-vs-gamma King gap is an AFTER-HOURS artifact — `irtBuildCsv` uses `tapeMap`+kingLatch,
`gammaProfileBuild` uses `tapeMapLive` DOM; both read live and agree at the open).
