What the design pass actually changed, checked against the visualisation anti-pattern catalog rather than taste:

1 · Colour now marks identity, never decorates a value. `$725` and `$913` were amber for no reason — money is not a status. Values wear ink; colour is reserved for what it MEANS: green/red for the day's polarity, amber for a level, violet for a node. That is four semantic colours, each with one job, which is also what keeps them legible together.

2 · tabular-nums on the table. Digits are now equal-width so every column aligns vertically — the direct answer to "aligned and symmetrical". A 13px row rhythm runs through all three columns and the candle's label baselines sit on the same grid.

3 · The spine segments have 2px gaps and rounded ends instead of abutting. Adjacent fills are separated by surface, never by a border — a border adds a line that carries no information.

4 · Columns are equal-width and bottom-aligned at nine rows each, so the rules run the full height and the block reads as one object. The blank in 2ND is the deliberate W.END gap you specified.

5 · The track is a solid hairline, one shade off the surface. It was dashed; dashing reads as "projection" when it is just an axis.

Two fields I would add, and one I would not:

EFF (55% vs ~68%) — range ÷ distance actually walked. It is the single number that says trend-or-chop, I computed it during the candle work and then dropped it. BODY (45%) completes the 40/45/16 so all three shape fractions are readable as text, not only as the spine.

I would not add O/H/L/C as columns. The candle already draws them, and four more rows of prices would push the block past the candle's height for numbers you can read off the picture. They belong in the candle's hover.
