## 1) Key level badges at their price (lsDealerProfile 2.52.3, ColumnBoard 1.10.0)
- Before: DealerProfile.cpp used the PANE edges for the on-screen test and then turned the HOD/LOD table rect (lsHodLod stretches it to
  the axis, so it covers the Key Levels column - status AXIS_FILL on: ES 479-634, CL 329-502, NG 255-428; HG 533-590 overlaps the column
  too) into a hard floor / ceiling for cb::stack. Every level whose line lay behind the table was squeezed against its edge and looked
  static (HG PFL 6.3180 drawn at ~6.343; ES PFH / PDH at the bottom; CL / NG many).
- Now the band is decided FIRST (cb::planKeys): under the IRT title row, minus the table side it covers, minus one row per edge marker.
  A level whose LINE is outside the band is not a badge: the nearest one becomes the existing "^ / v name price (distance)" edge marker
  (a level behind the table beats one beyond the pane - it is nearer price). Inside the band a badge stays at its price or is pushed at
  most 2 badge heights (the slanted tick); a badge pushed further is taken out (farthest from price first, then re-stacked): near the
  band edge (line within 3 badge heights) it becomes that edge's marker candidate, elsewhere it is dropped and counted. A marker row is
  reserved only while that edge has a marker. The weekly POC marker keeps its own row.
- cb::stack gets the 3rd (forward) pass its comment promised. Fuzz (20,000 scenes) found no case where the 2-pass stack left the band
  (the drop step already keeps the total inside), so the pass is a guard, not a visible fix.
- Status KEYS_COLUMN: "badges from y T to B", "(2.52.3) behind table / title -> edge marker N", "pushed past 2 badge heights N",
  "edge markers N (^ name / v name)".
- Nothing else drawn changes; no settings change (PLUGIN_VERSION 2.52.3, parameter version unchanged); no hovers.

## 2) One London rule everywhere: London ends at the earlier of 07:30 CT and the market's RTH open
- lsHodLod 2.17.8 (HodLodLogic.h): a London bar starts at / after 02:00, BEFORE the RTH open (svl::rthOf: GC / EU 07:20, HG 07:10) and
  ends by 07:30 - exactly KeyLevelsLogic.h's rule (the Dealer Profile's LonHI / LonLO badges: svl ON = bar start before the open), so the
  HOD/LOD table's LonHI / LonLO sweep levels = the badges on the same chart. lonB() (London complete) = min(07:30, open). Was 07:30 for
  every market (GC / EU / HG London included RTH bars).
- lra.key_levels (LH / LL for the Reader / studies): the same rule on bar END stamps (end in (02:00, 07:30] and start before
  lra.markets' open: GC / EU 07:21, HG 07:10); London levels valid from the end of London's last bar. lra.hodlod_levels and
  KeyLevelsLogic.h already stopped at the open (unchanged). Edge note: with lra.markets' GC open 07:21 vs svl 07:20 the same 3-min
  bars are London in both (07:18-07:21 in, 07:21-07:24 out).

## 3) Kings on wide days (lsLiquidityProfile 0.73.1)
- Kings were allowed only between today's high - ADR and today's low + ADR; on a day whose range is over 2 ADR that window is empty
  (ES 11-04 status "today's range is over 2 ADR: no kings"). Now (lqp::kingWindow, SDK-free): on such a day the last price +- 1 ADR.
  Status KING_NODES range: "wide day (range over 2 ADR): last price +- 1 ADR". No settings change.
