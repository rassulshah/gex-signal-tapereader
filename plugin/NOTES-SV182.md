# lsSessionVWAP 1.8.2 (2026-10-28)
Request: Rassul 11:27 CT "did you fix the session vwap. as you can see it isnt working properly. can you fix this too and test it" (screenshot: the Update window of his ES 3m chart showed VWAP unticked, VWAP colour black, 1 px; bands / overnight / prior unticked; pivot ticked).

Root cause: 1.8.1 made the chart read IRT's own per-indicator parameter set. Its parmsInit(7) copied the 1.8.0 record into the new set field by field, and that record held VWAP off / black / 1 px - values IRT had stored from the 1.5-1.8.0 windows while those versions drew from the per-market file (so nobody saw them). 1.8.1 accepted the set (it only refused an all-zero set) and its parmsLoad returned without filling the window, so the window showed the raw values and the chart drew no session VWAP. At 11:25-11:26 he unticked +1/-1/+2/-2 SD, overnight and prior (Settings-dialog.log items 3/5/7/9/12/13); the chart then drew only the pivot VWAP (the green 0x22C55E line). The brown 4 px line on the screenshot (RGB 167,84,84) is no SessionVWAP colour.

Fix (1.8.2): parameter version 9; parmsInit saves the intended defaults for every older set (VWAP magenta 2 px, +-1 / +-2 SD bands 1 px, overnight set, prior RTH VWAP, 3-bar pivot VWAP green / red 2 px); the legacy record (VWAP off + colour 0 + width index 0) is read as the defaults if IRT keeps it; parmsLoad always fills the window with exactly what the chart draws (black swatch shows the colour drawn, off rows greyed); status file STYLE line = the drawn style. Rows / layout unchanged; no new header (gex-build.bat unchanged).
