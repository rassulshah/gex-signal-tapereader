# lsBreakout 1.4.0 - the BO zigzag carries across the 5 PM CT session break (2026-11-04)

## Request
Rassul, 2026-11-04 morning: "BO 5PM - yes". Before this, the swing walk that gives the BO / BD pivots (bba::swingBreaksPx, 3-bar
ZigZag) started again at every Globex open (17:00 CT, bba::boSessKey). So the evening's first candles had no swings to break and the
afternoon's intact swing highs / lows were forgotten at 17:00. Now the walk runs on across the break.

## What changed
- `BigBidAskLogic.h`: `swingBreaksPx(..., rev, carry)` and `boFromCandles(..., ftTie, carry)` (default false). With carry the walk
  never resets (`swgCarry`): direction, leg extreme and swings run on across 17:00 CT (and the Sunday open). Memory stays bounded and
  TIME-anchored (`swgTrim`): at each new session the bars older than the previous session's start are dropped (never the current leg's
  extreme); over swg::ZZ_CAP - 1 bars (1-min charts) the older half is dropped. A pure function of the candles (no repaint).
  lsBigBidAsk passes nothing: per-session walk, decisions and `bba::VERSION` 1.32.0 unchanged (it is off his charts anyway).
- `BreakoutLogic.h` 1.4.0: `Engine::zzCarry = true`, used only with zzRev > 1 (`carryOn()`); the zzRev = 1 parity path stays per session.
  Record files' first line: `# lsBreakout 1.4.0 | ES ESZ6 180 | zz_rev_bars 3 | ft_tie 1 | zz_carry 1 | ...`; version field of every
  line `1.4.0-zz3`. Status: `RECORDS,...,zz_rev_bars 3,ft_tie 1,zz_carry 1,lines written ...`.
- `Breakout.cpp` 1.4.0: version literals + description only. No settings (SS_SAFE_DIALOG), no hovers, no new includes (gex-build line
  unchanged).
- Unchanged: BO / BD rules (the 20-bar counter-trend window is still clipped at the session start), follow-through tie, Rly (RTH
  waves - never cross 17:00), Pb (chart-wide 3-bar pivots - wave origin already crossed the break), records layout / dedupe, labels.

## Why not the bo_eve "carry.txt" rule exactly
carry.txt (150 fired, strict follow-through) was made by changing boSessKey to the CALENDAR day. That carries 17:00 -> 23:59 into the
day session but starts a NEW walk at midnight CT. With the tie it gives 152 fired, but 3 of its changes are midnight artefacts
(Oct 27 00:18 BD, Oct 28 00:21 BO, Oct 30 00:42 BD) and it loses Oct 22 17:03 BO / Oct 25 18:27 BD. The 1.4.0 rule is the true carry
(no reset anywhere); it equals an UNBOUNDED walk on ES Oct 20 - Nov 3 bit for bit (the trimming changes nothing there).
