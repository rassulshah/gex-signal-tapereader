What changes in the code

the unitone space at the strip's own font, measured with getTextWidth(" ") — not a hard-coded pixel count, so it holds at font 8 and font 14 alike
SPX (right edge)the strike moves left by one space; the % stays right-justified at the pane edge. The column is one space wider, so the bars, the level lines and the price area all start one space further in — everything that reads colW follows automatically.
SPY (left edge)the % column's start goes from colW/2 to colW/2 − 2 spaces. The strike stays at the pane edge; the strip's own width is unchanged, so the SPY rail does not move.
one placegpl::tapeCols(font, side, spaceW) in the logic header, pinned by Gate B — today the two offsets are computed inline in the render, once per rail.
Note on the SPY strip: at −2 spaces the widest case, a three-digit strike beside −100%, leaves ~16 px of air — still clear. A fourth digit (it will not happen on SPY) would touch.
