# ARCHITECTURE AUDIT — GEX Signal Tapereader (v10.58 → v11.0 LOCKDOWN)
Date: 2026-08-18. Scope: the whole of `v10.js` (14,369 lines, 664 functions), the docs, rules.json, the export, the
review pipeline, the Analysis/Testing tabs. Method: four independent line-range audits (appendices A–D, every block
inventoried with callers grepped across the whole file and tests grepped per function), then this synthesis.

## 0. The verdict in one paragraph
The app is sound at its core — feed capture, tape parse + sync gate, SMA five-state, node map, leg engine, latched
trigger, Map, features registry, effN/promotion, exporter — but it has grown by accretion: ~1,600 lines are
unreachable from `render()`/`tick()`, the same idea is computed several ways (accumulation ≥6 readings, direction tilt
4, King movement 3, node identity tags ~10, handoff ≡ Map transfer), and the learning loop has never closed end to
end (no day file has reached `data/`, the nightly output is never read back, two user-priority outcomes resolve as
false misses after a reload, and the promotion bar is structurally unclearable once repo history exceeds the
localStorage window). None of that is a reason to rewrite; it is a reason to (1) fix the recording/learning path so
the data collected from tomorrow on is trustworthy, (2) add the node ledger as the base layer, (3) collapse
duplicates onto one reading each, (4) remove the dead code, and (5) rewrite the docs around one stack — then lock.

## 2. Verdicts (what changes in v11.0)
### 2.1 KEEP + FIX (the learning path — highest priority, this is what "collect data" depends on)
- G7 reload bias: `LEG_PB_LOG` persisted per day (recorder) and outcomes return **null**, never 0, when the log is absent.
- G4/G9 local truth: resolved feature records mirrored to IndexedDB per day (`repoUpsertFeat`), `featStats` reads IDB
  days (async, cached) so local truth is not the localStorage window; `proposalClearsBar` drops the "reviewer n within
  20% of local n" test (kept: local eff n ≥ 20, ≥3 walk-forward sessions, no regime flip).
- Bug 6/7: `dirFactorStats` uses `dirNum` as vote fallback (handoff/trigger/pbDetect rows get vote split); `leg.roll`
  records the vote the grade actually uses.
- G5: `ruleLocalRate` maps `node.tap.*` / `node.pol.*` / `node.rocDay.*` to the ④ DEFLECTIONS slices and `kill.*` to
  its feature key, so they can be measured locally.
- G8: the READ sentence + voiceId + leg dir are recorded on the `dir` record (brief contradiction #1 becomes measurable).
- G2/G3: `pipeCheck` also fetches `learning/log/<lastTradingDay>.json`; Analysis "REVIEW" renders the v2 weekly
  fields (headline, features, contradictions, calibration, killList, missingFields) AND the nightly log line.
- G11: auto-export success flips the save banner; one `saveState()` source.
- Version: one `VERSION` constant used by header/footer/export/log; `resolveFeatureOutcomes` once per tick; click
  delegation wired before the futures early-return.
### 2.2 NEW: the node ledger (layer 1)
`nodeLedger(sym)` from `feedSeriesAll` + candles: per node {k, src, first, peak, peakAt, last, state, m15, fromPeak,
gone, transfers[], touches[{t, react: deflect|through|stall, dir}], influence:{toward, away}} — persisted per day in
the recorder + IDB, exported as `ledger`, Analysis "NODES" section (per node: life, touches, reaction rate, n),
brief section. It becomes the ONE source for accumCanon (tape strip only as a faster confirm), mapNodeState,
legNodeDissipating/Building, and the node hover.
### 2.3 MERGE (one reading each)
- Accumulation thresholds: `ACM_BAND` / `HANDOFF_*` / `MAP_*` → one set (`ACM_UP=8, ACM_DN=−8, ACM_DROP=25`); the
  leg engine's `to` node must actually be building (acm or 'Building'), not merely ≥PB_MIN_PCT.
- Handoff ≡ Map transfer: the leg engine keeps `handoff` (it needs the leg context) but reads the SAME node states as
  the Map (`mapNodeState`), so both fire on the same evidence; `leg.handoff` keeps the lead-time claim, `map.transfer`
  the price claim.
- Features: `roll` → `dir.kingRoll` (retire `roll`); `drift` → `dir.drift` (retire `drift`; bands ride on dir.drift).
  `defl_ant` / `reaction` stay SHADOW.
- Analysis: ② strips → Testing ②③④ (Analysis keeps PROMOTED only); ⑦ → footer hover; YOUR CALLS out of ⊕; ⑥ →
  "REVIEW (nightly + weekly)"; new "NODES (ledger)".
- `accumBlock` → `nodeMapBlock` directly; `_frameRecOf` once per bar; `nodeMapModel` memoised per poll.
### 2.4 RETIRE (dead — zero callers or unreachable from render/tick; data preserved where any)
Part A: breakoutConviction, trendIsUpish/Dnish, trendCodeOf, saveLog/LOG, outOfSyncBlock, parseKingDollarSign,

Part B: gridFor/signalGrid/combinedGrid + tips, readLine, structuralReadHtml + structuralBox/Warn, stageTimeline,

nodeMapSentence(+Html), _nmRole/_nmB/_nmAcc, studyCite/studyTag, dispVal, dirColor, stepIcon; kingBlock chain
(kingSparkline, kingPathSigMoves, kingReadHtml, projChartHtml, projTaperHalf, sessionBoundsCT) — parked code kept
ONLY where a test pins it, marked PARKED in the source.
Part C: ruleGet, acmChipHtml, _escHtml, tapCol, gradeChipHtml, activityPillHtml, zoneGGlyph, readOddsAllowed,
identity gradeDisp; NODEHIST becomes the ledger's touch source (no longer write-only).
Part D: kingBlock, readBlock, confluenceThesis/Strip, timelineSvg, convergenceSvg, _kpi, _accBar, analysisStats

## Latent bugs / inconsistencies
1. **Two "m15" horizons.** `accumCanon.m15` = 2 tape-strip samples (≈6 min) for SPY strikes with a strip, but 15 feed samples (≈15 min) for SPXW-derived lanes / stripless strikes (8409–8428). Every ±8 threshold (handoff, map, nodeGrade rocNow) is applied to both as if they were the same quantity; the SPXW lanes will read "acm/dec" far more often.
2. **Thresholds defined three times with the same numbers** (`ACM_BAND=8`; `HANDOFF_ACM=8/DEC=-8/DROP=25`; `MAP_ACM=8/DEC=-8/DROP=25`). Any tuning (or promoted `threshold` proposal) will move one and not the others; a proposal target can only reach `DIR_WEIGHTS` keys anyway (`promoDirWeightKey`), so none of these are promotable despite the "one constant" doctrine.
3. **Off-peak computed two ways.** `legNodeDissipating` uses model `L.pct` against accumCanon's `session.peak` (peak sourced from feedStructMap/livePctAt magnitudes); `mapNodeState` uses accumCanon's own `fromPeak`. If model pct (tape/DOM %King) and feed magnitude differ, the leg says "dissipating" and the Map says "holding" for the same strike on the same bar.
4. **`legNodeBuilding` is satisfied by any node ≥ PB_MIN_PCT** (8568) — the handoff `to` does not require accumulation, so "the new one forming" is really "the nearest lower meaningful node when the old one bleeds"; the recorded `leg.handoff` rule condition text (11012) claims otherwise.
5. **nodeGrade rocDay: label vs score disagree.** Score uses ±15 (9591) but the recorded label uses `acmLabel` at ±8 (9592) → a node labelled "Acm" (+10%) scores 0 for rocDay.
6. **Spine is per-poll, engine per-bar.** `spineBarKey` includes `S.price` (9232) so `spineOf` (and thus `directionGrade`, `nodeGrade`, `decisionCell`, `inPlayZoneOf`) recompute on every price tick, while `legEngine`/`nodeFlow` are keyed by bar (`legBarKey`). The header comment ("Computed ONCE per closed bar") is wrong; the recorder can capture a different in-play node/grade than the one shown one tick earlier.
7. **`nodeMapModel` is uncached and rebuilt many times per render.** In this slice alone it is called by `nodeHistSample`, `legCtxOf`, `directionGrade`, `inPlayZoneOf`, `tradeFrame` (→ once per `nodeGrade` via the kill path, i.e. once per watch row), `nodeFlow`, `deflZonesBlock`, `briefLine`. 8. **localStorage writes inside pure-looking readers / per poll:** `accumCanon` calls `acmDaySave()` on first-seen and on each new peak (8438, 8446) — invoked dozens of times per render; `nodeHistSample` saves every poll (14317); `deflTrigger` saves per bar. Fine functionally, noisy on a 2 s poll.

## (3) THE LEARNING PIPELINE END TO END

**Trace of one recorded bar (SPY, closed 3-min bar #k):**
1. `tick()` → `recordNodeSnapshot('SPY')` (L2313) once per closed bar → `featureCtx` → `featRecordAll(sym,ctx)` → 28 records each stamped `regime{tag,opex,event}` + `model{rulesAsOf,weightsHash}` → written **twice**: `snap.feat` (into `day.snaps.SPY[]`, cap 200) and, via `featEnqueue`, `day.feat.SPY[]` as `{key,t,bar,n,px,session,rec,hit:null,mfe:null,mae:null,resolved:false}` (cap 160 bars) → `recorderSave` (LS `gpts_recorder_v7`, RECORDER_DAYS=10, oldest day dropped on quota) → last 12 snaps mirrored to IDB (`repoUpsertSnaps`).
2. ≥10 bars later `resolveFeatureOutcomes` → per record: fwd {px0,pxEnd,mfe,mae,net,n,first,kingReached,partial,frame} → `f.outcome(rec,fwd)` → sets `hit, mfe, mae, out, drift(=hit), frame, partial, fwdUsed, resolved:true` → `featStatsInvalidate()`.
3. 15:01–16:00 CT `repoAutoExportTick` → `repoExportDay(TODAY,true)` → payload = `buildDayExport(TODAY)` with `snaps` replaced by IDB snaps + `exportedAt`. **Fields:** `schema, projReview{scorecard,recommendations}, version, rulesAsOf, model{rulesAsOf,weightsHash}, effN, date, generatedAt, horizons, legend, syms, snaps{SYM:[{t,bar,px,h,l,king,tking,kd,proj,xm,ep,rg,deriv,feat{28 keys},inplay,nodes[],sig{trend,king,srb,breadth,conf,…},out5,out10}]}, events, feat{SYM:[FEATREC…]}, act{SYM:[]}, matrix[] (one row per sym|bar: `key.field` columns + regime/opex/event/rulesAsOf/weightsHash + dirHit/deflHit/contHit/tgtHit/mfe/mae/partial), matrixLegend, nodeHist, sessionRoll, futures, event, flrCeilHist, features[28], rules{55 ids}, questions[…]`. Written to the picked repo folder handle (`dataDir` in IDB kv) as `data/<date>.json`; if no handle/permission → browser download (`pipeNoteSave(...,'download')`).
4. Local scheduled task "GEX data push" (15:30) commits `data/<date>.json` → GitHub.
5. **Nightly (LLM, cloud):** clone → read `data/<date>.json` + `learning/rules.json` + last 3 logs → contradictions per bar (READ≠dir.verdict, divergence on confirmed trend, grade A <30%), regime+baseline+per-factor vote split, `learning/log/<date>.json`, "power out loud" line, one-line pre-open brief → deliver via device bridge / Drive inbox / chat → local task commits.
6. **Weekly (LLM, Saturday):** all data + logs → per-rule n/rate/MFE/MAE/vote split/regime/lift, calibration, walk-forward, challengers, kill list, proposals (`clearsBar` asserted) → writes `learning/rules.json` (rules/proposals/challengers/killList; weights & promoted untouched) + `review/<date>.json` (v2: span, grade, features[], contradictions, calibration, challengers, killList, questions, missingFields, selftest, headline).
7. **Read-back (panel):** `pipeCheck` every ≥10 min: HEAD-ish fetch of `data/<today>.json` (pushed?), `review/<lastTradingDay>.json` (→ `ANALYSIS_REVIEW`, `P.reviewLine`), `learning/rules.json` (→ `rulesIngest` → `rulesApply` → `applyProposals`; deferred to after 15:01 mid-session).
8. **Promotion:** `applyProposals` accepts a proposal only if `p.clearsBar===true` AND `proposalClearsBar(p)`: local eff n ≥ PROMO_MIN_N(20) for the feature key resolved by `proposalFeatureKey`; `p.n` within 20% of local eff n; ≥3 locally recorded sessions strictly after `p.madeOn` with rate > baseline; no trend/chop flip in `p.regimeSplit`. Then `promoApplyWeight` (DIR_WEIGHTS[k], DIR_WEIGHTS_SOURCE='measured') / `promoApplySwap` (TREND_WINDOW+TREND_DOM or CFG.trendMA; anything else recorded inert) / `promoApplyKill` (P.kills → `killCheck` caps grade at C) → persisted `gpts_promo_v1`, event logged, `doc.promoted` appended, `rules[rid].tier='measured'`. `ruleTier(id)` shows 📊 only if promoted here AND local effN ≥ 20. `promoDemoteCheck` weekly reverts after 3 strikes.

**Breaks / gaps found (ordered by severity):**
- **G1 — the loop has never closed.** `data/` has no day file, `learning/log/` and `review/` are empty, `rules.json` has no proposals/challengers. Auto-export depends on a File-System-Access folder handle with persisted permission; without it the file goes to Downloads (`saveHow:'download'`) where the push task does not look. The manual "📥 Save" writes `gex_<date>.json` (different name from `data/<date>.json`).
- **G2 — the nightly output is never read back.** The panel fetches only `review/<day>.json` (weekly) and `learning/rules.json`. `learning/log/*.json` and the nightly "one-line pre-open brief" have no path into the panel; the Analysis section is titled "NIGHTLY REVIEW" but shows the weekly file.
- **G3 — review schema mismatch.** Analysis ⑥ renders `R.worked / R.missed / R.why / R.discovered / R.recs` (an older shape). The v2 weekly review has `features[], contradictions[], calibration[], challengers, killList, questions, missingFields, selftest, headline` → only `headline` (via `pipeReviewLine`) will show; calibration/contradictions/missingFields are silently dropped. The panel reads `challengers`/`killList` from rules.json only.
- **G4 — "local truth" cannot reach the bar.** `featStats` reads LS only (≤10 days nominal; realistically fewer given record volume — see featEnqueue row). Promotion needs local eff n≥20 (=200 bar-records of one key; FEAT_KEEP_BARS=160/day so ≥2 retained days) *and* the reviewer's `n` within 20% of local eff n. The reviewer's n spans all repo days; local spans ≤10 → once the repo has more than ~10 sessions the 20% test fails structurally, and nothing can ever be promoted → every ⚖ stays ⚖ forever. Also ambiguous whether `p.n` is raw or effective in the brief's proposal example.
- **G5 — sub-rule ids are unmeasurable locally.** `ruleLocalRate` maps `dir.[ABC]`, `node.grade.[ABC]`, `decision.*` to featStats buckets; `node.tap.*`, `node.pol.*`, `node.rocDay.*`, `drift.conf`, `kill.*` fall through to `byKey[id]` → n=0 always → kill-list entries can never clear the bar (`proposalFeatureKey` returns `kill.*` → nothing local measures it), and questions like `tap_decay`/`pol_char` never leave "proposed" even though ④ DEFLECTIONS computes exactly those slices.
- **G6 — questions are decorative.** `when` conditions are never evaluated; `questionQueueHtml` uses the whole feature's rate; `outcome` names (dirMove/nodeHold/pbFormed/deflHit/contHit/tgtHit/driftMove) map to nothing; the reviewer's `questions` output is never read.
- **G7 — reload bias in leg.pbPredict / leg.handoff.** Outcomes read in-memory `LEG_PB_LOG`; after any reload (or after the 200-entry trim) pending records resolve as `hit:0`. The reviewer is asked to report exactly these rates ("prediction accuracy", "lead time", "false-handoff rate") from biased data. Also `leadBars` false-handoff needs `resolved` history that only exists per bar.
- **G8 — contradiction check #1 is vacuous.** READ verdict == `d.dir` by construction; the READ *sentence*/`voiceId` (leg voice may say "downtrend… sell level" while dir=SIDE, the very case the brief cites for 2026-08-18) is not recorded anywhere.
- **G9 — LS eviction destroys outcomes.** Only `snaps[].feat` (records, no hit/mfe/mae) is mirrored to IDB; the resolved queue lives only in LS. After eviction, local outcome history is gone; the exported day files (which contain it) are never read back. Local promotion truth is therefore ≤ the LS window; walk-forward "3 sessions after madeOn" competes with the same window.
- **G10 — export bloat/duplication.** Every day file carries the full `rules` map, `features`, `questions`, `snaps[].feat` AND `feat[]` AND `matrix` (three copies of every record). The brief never mentions `matrix` or `projReview`.
- **G11 — pipeline indicators disagree.** Save banner (`SAVED_TODAY`) vs footer/⑦ (`saveState()`); auto-export success does not flip the banner.
- **G12 — model stamp is weak.** `weightsHash` covers DIR_WEIGHTS only; swaps (TREND_WINDOW, CFG.trendMA), kills and NODE_WEIGHTS are not in the hash, so a promoted swap is invisible on the record.
- **G13 — voting features vs recorded votes.** `leg.roll` votes into the grade only when `confirmed` (or `weakening`), but its record `vote` is set at `count>=LEG_ROLL_SIGNAL(2) && !weakening` — the recorded vote is not the live vote; the factor table measures a different rule than the one that moves the grade.
