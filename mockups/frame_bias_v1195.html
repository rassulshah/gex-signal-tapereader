Two real bugs, and you spotted one of them.

1 · GK above the King — you are right, it is mislabeled. skRoles(pct, kingK) is never given price, so it cannot know which side of the King price is on. It picks the strongest significant node within 6 strikes on either side:
 King 7670 · neighbours 7665 (25%) below, 7675 (63%) above → picks 7675 because it is stronger
Price is at SPX 7665, so the King is below price and the "gatekeeper" is above both. It gatekeeps nothing. The comment says "the nearest significant node standing between price and the King" — the code never implemented that. Fix: pass price in, consider only nodes strictly between price and the King, and when there are none say clear path rather than naming one.

2 · SKEW is grayed out because its range is dead. Live: v=0.11, lo=2.2, hi=2.2, n=240. The direction test is gated on if(hi>lo), and with a degenerate band it silently never fires.
⚠ The deeper fault: the current value and the history are different metrics. v is now skew25 (25-delta put IV − call IV, ≈0.11) while the 240 stored samples are the old published header skew (≈2.2). It is being compared against a range built from a different quantity — Pattern 1. The history has to be versioned by source and reset when the source changes, and a dead range must SAY it is dead rather than reading as neutral.
Two that are not bugs.

ROLL is correct. {ok:true, dir:0} — the King genuinely has not moved a full strike. It only looked broken because a neutral renders as a grey dash, identical to unavailable. The ↑/↓/→ change fixes exactly that: it will read →, not a dash.

ACCUM's direction is right; its sample is too thin. Live: dUp +$90M, dDn +$5M, dir −1, text "upside building faster". That is coherent — building above price is resistance stacking, which is bearish. The doctrine and the sentence agree.
⚠ The flipping is n=4, and the minimum is 4. Only four strikes sit within ACCUM_REACH=5 of price, so one strike moving flips the share. The window (30 min) is fine; the strike reach is what starves it. I would widen the reach and show n on the badge so a thin read is visible rather than merely unstable.
