Circles, and what each state looks like

Quiet — solid, no ring, no motion. Most nodes, most of the time.
Accumulating — green rim, sonar rings leaving outward. Size is being added.
Dissipating — fill wanes, edge dashed and drifting. It is coming apart.
Receiving a roll — blue rings collapsing inward. Money arriving.
Balanced — hollow. The gamma is real but the legs cancel, so no side is asserted.

Direction is the whole trick

Rings leaving a node mean it is growing; rings arriving mean it is being fed by a roll. You can read which node is winning without reading a number, and the two motions are opposite so they can never be confused at a glance.

Arrows: dashes flow toward the destination

The path is drawn twice — a dim static line for the route, and a bright dashed overlay whose offset animates, so the dashes travel from source to destination. Blue for a roll up, red for down. Speed is fixed, not scaled to size: a fast-moving dash would read as urgency and that is what the label is for.

Restraint — the rule I would enforce in code

Motion is expensive attention. Only nodes whose 15m change is decisive animate, capped at three at once, cycles at 2.2–3.2s so it breathes rather than flickers. Everything else sits still. Press "Everything animates" — with six nodes moving, the rail becomes the busiest thing on screen at exactly the moment you need to read it calmly.

prefers-reduced-motion disables all of it, and so does the third button — which I would ship as a real setting, because on a second monitor during a fast tape some people will want it off.

Cost, since this runs all session

Every animation is CSS on an SVG element — no JS timer, no re-render. The panel already repaints on its own cadence; these compose on the GPU and cost effectively nothing.
